# HDFS-15323 — StandbyNode fails transition to active due to insufficient transaction tailing

## Commit

- **Hash**: `8358d7c1759`
- **日期**: 2020-05-04
- **涉及文件**: `hadoop-hdfs/.../qjournal/client/QuorumJournalManager.java`、`namenode/ha/EditLogTailer.java`；测试 `TestStandbyInProgressTail`

## Diff 机制分析`

QJM 每次 RPC tail edit 最多取 5000 条（`dfs.ha.tail-edits.qjm.rpc.max-txns`），高负载下 SBN 一次 tail 拿不完所有新事务；而 `catchupDuringFailover`（ZKFC 触发 SBN→ANN 切换时）只调一次 `doTailEdits` 就宣布追上，实际还有残余事务没加载，切换后 ANN 以缺事务的状态启动，failover 失败或数据落后。修复把 `catchupDuringFailover` 改成 do-while 循环，直到一次 tail 拿到 0 条事务为止真正追平，并补充 tail 耗时/间隔指标。

## 影响评估

**高**。这是 HA failover 在高写入负载下失败的根因修复；没它，切主可能丢事务或拒绝服务。HA 集群必修。
