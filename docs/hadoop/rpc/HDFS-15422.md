# HDFS-15422 — Reported IBR is partially replaced with stored info when queuing

## Commit

- **Hash**: `bf229135caf`
- **日期**: 2021-02-24
- **涉及文件**: `hadoop-hdfs/.../blockmanagement/BlockManager.java`（+10/-8）

## Diff 机制分析

Standby NN 处理增量块报告（IBR/FBR）时，遇到"out-of-date generation stamp or state"的块会先入 `reportedBlocks` 队列延迟处理（避免 failover 竞态下误判 corrupt）。旧代码入队的是 `storedBlock`（NN 内存中的旧信息），把 DN 上报的 `replica`/`block` 信息覆盖掉了；等队列后续处理时拿旧信息与新状态比对，导致处理结果错误（HDFS-6289 时期就留了 TODO 怀疑这里写错）。修复就是把入队对象改为上报的 block。`reportDiffSortedInner` 与 `processAndHandleReportedBlock` 两处同样问题一并修正。

## 影响评估

**中**。影响 Standby/Observer 的块状态收敛正确性，可造成 failover 后副本状态不一致（与 HDFS-15187 同族问题）。主 NN 日常热路径行为不变。

## apply 检查结果

**clean**。
