# HDFS-16233 — Do not use exception handler to implement copy-on-write for EnumCounters

## Commit

- **Hash**: `cd7c34f9b40`
- **日期**: 2021-09-24
- **涉及文件**: `hadoop-hdfs/.../server/namenode/QuotaCounts.java`（+2/-7）

## Diff 机制分析

`QuotaCounts` 内部维护一组 `EnumCounters<Quota>`（storage space / namespace 配额计数）。copy-on-write 语义此前靠 try/catch 实现：`get(...)` 时若 counter 是共享引用则捕获 clone 抛出的异常再复制。本 patch 把异常驱动的隐式 COW 改为显式判断后 clone，删掉了为 COW 服务的异常处理路径。行为等价，但去掉了 quota 读取/累加路径上构建和捕获异常的开销（exception 在 JVM 里是昂贵的堆栈快照对象），并让代码语义清晰。

## 影响评估

**低**。QuotaCounts 在 addBlock、mkdir、setQuota 等 NN 写路径每次都会经过，但改动节省的是偶发的异常构造开销（仅在 COW 触发点），常规热路径收益很小。属于代码质量 + 微优化，用户点名保留。
