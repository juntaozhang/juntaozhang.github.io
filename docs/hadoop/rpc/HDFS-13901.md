# HDFS-13901 — INode access time is ignored because of race between open and rename

## Commit

- **Hash**: `8ef6c0aab24d16cf954f9a90f304a9d117cf119c`
- **Date**: 2019-10-22
- **涉及文件**: `FSDirStatAndListingOp.java`、`FSNamesystem.java`、`INode.java`（+测试）

## Diff 机制分析

getBlockLocations 先在读锁内解析路径返回结果，之后为更新 atime 又在写锁段
二次 resolvePath——open 与 rename 并发时二次解析可能命中已改名的路径，
对错误 inode 更新 atime，或 inode 已被删导致 atime 更新静默丢失/报错。
修复：第一次读锁解析时把 INodesInPath 一并带出，写锁段直接基于其 inode
用 `inode.getFullPathName()` 重解析，并新增 `INode.isDeleted()`（沿父链查
是否还挂在 root 下）做防御判断。

## 影响评估

**低** — getBlockLocations（最高频 NN 读 RPC）atime 语义的正确性修复；
不影响返回结果，只修 atime 准确性及极端竞态下的异常。
