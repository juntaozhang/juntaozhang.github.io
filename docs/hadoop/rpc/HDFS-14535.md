# HDFS-14535 — Short-circuit read 请求 8KB buffer 造成大量堆分配

## Commit

- **Hash**: `b082628e5a3`（branch-3.1，2019-06-04，huzheng/openinx）
- **涉及文件**（1 个，+2/-1）：`BlockReaderFactory.java`（hadoop-hdfs-client）

## Diff 机制分析

Short-circuit read（短路本地读）建立共享内存通道时，客户端要向 DN 通过 Unix Domain Socket 发送 `requestShortCircuitFds` 请求。原实现把这个极小的控制请求包进 `new BufferedOutputStream(peer.getOutputStream())`，使用默认 8KB 缓冲区——**每建立一次短路读连接就分配一个 8KB byte[]**。

对 HBase 这类高频短读场景，每个 `BlockReaderLocal` 获取 slot 都走这条路径，连接复用率低，8KB 分配以高频率进入 young GC，造成可观的 heap 分配压力和 GC 开销。

修复：`BufferedOutputStream` 显式使用 `SMALL_BUFFER_SIZE = 512` 字节（请求包远小于 512B，语义不变）。

代码路径：DFSInputStream → `BlockReaderFactory.createShortCircuitReplica` → `requestFileDescriptors`（客户端短读热路径）。

## 影响评估

**评级：低-中**。典型 HBase 集群可观测的 young GC 改善；对非短读场景无影响。属于客户端读路径 GC 热路径优化。
