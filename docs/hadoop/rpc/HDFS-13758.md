# HDFS-13758 — DatanodeManager 应对"非 under construction 的恢复块"抛异常

## Commit

- **Hash**: `7a115e8de47`（branch-3.1，2018-08-14，chencan）
- **涉及文件**（1 个，+5/-2）：`DatanodeManager.java`

## Diff 机制分析

`DatanodeManager.getBlockRecoveryCommand` 从 DN 取待恢复块构造 `BlockRecoveryCommand`，原代码 `assert uc != null`——assert 在生产（-disableassertions）下是 no-op，若块实际已不处于 under construction（并发 complete/删除竞态），`uc` 为 null 时后续 `uc.getExpectedStorageLocations()` 直接 NPE，NN 侧错误处理路径混乱，DN 收到的是误导性错误。

修复：显式判空并抛 `IOException("Recovery block ... where it is not under construction")`，错误语义清晰、走正常 RPC 错误路径。

代码路径：NN 心跳响应组装（`DatanodeManager.getDatanodeCommand` → `getBlockRecoveryCommand`，每次 DN 心跳都可能走到）。

## 影响评估

**评级：低**。把生产环境潜在 NPE 换成有意义的异常；竞态本身罕见，但修复后故障定位成本低。
