# HDFS-13792 — Fix FSN read/write lock metrics name

## Commit

- **Hash（rel/release-3.1.1..rel/release-3.2.0）**: `2e4e02b4df59f94b26567660638d58ad9ebc121e`
- **Author**: Yiqun Lin（代码贡献者 Chao Sun）
- **Date**: 2018-08-07
- **涉及文件**:
  - `hadoop-common-project/hadoop-common/src/site/markdown/Metrics.md`（+4/-2）

**注意**：这是一个**纯文档** commit——只改 Metrics.md，不改任何 Java 代码。
实际指标名在代码中从来就是带 `Nanos` 后缀的（见 HDFS-10872 引入时即如此），
被修正是**文档中写错的名字和单位**。

## Diff 机制分析

`Metrics.md` 的 NameNode metrics 表格中：

1. 把 `FSN(Read/Write)Lock<OperationName>NumOps` /
   `FSN(Read/Write)Lock<OperationName>AvgTime` 修正为
   `FSN(Read/Write)Lock<OperationName>NanosNumOps` /
   `FSN(Read/Write)Lock<OperationName>NanosAvgTime`——补上代码里一直存在但文档遗漏的
   `Nanos` 后缀。
2. **AvgTime 单位由 "milliseconds" 更正为 "nanoseconds"**（这是文档中最误导的一点：
   按毫秒读数会差 6 个数量级）。
3. 顺带新增两行文档，记录 HDFS-13686 引入的
   `FSN(Read/Write)LockOverallNanosNumOps` / `...AvgTime` 指标。

## 与 HDFS-13686 的关系（交叉引用）

HDFS-13792 是 HDFS-13686 的**文档收尾/修正**，两者是配套关系：

- HDFS-13686（见 [HDFS-13686.md](./HDFS-13686.md)）在代码中为每次锁记录新增
  `FSN(Read|Write)LockOverallNanos` 聚合指标，但**没有同步更新 Metrics.md**；
- HDFS-13792 的文档补丁在补上 `Nanos` 后缀修正的同时，把这两个 Overall 指标也写进了文档。
  换言之，如果只 cherry-pick HDFS-13686 而不带 HDFS-13792，功能可用但官方文档缺项；
  反过来 HDFS-13792 单独 cherry-pick 只是文档修正，无运行时影响。

## 对 RPC 调优/排障的价值评估

**中**。

- 运行时行为零变化，不影响 RPC 性能本身。
- 价值在于**排障时避免误读指标**：若运维按 3.1.0/3.1.1 时代的官方文档去找
  `FSNWriteLockCreateNumOps`（无 Nanos 后缀）或把 AvgTime 当毫秒读，会直接查不到/
  误读数据。对依赖 JMX 指标做 NameNode 锁竞争（进而定位 RPC 延迟）分析的团队，
  文档正确性是排障前提，但不算功能性改进。

## 是否值得 cherry-pick 到 3.1.1

`git cherry-pick 2e4e02b4df5` **干净应用无冲突**（4 增 2 删，仅 Metrics.md）。
没有运行时风险；如果维护内部分支文档/指标字典，带上它有百利无一害，
