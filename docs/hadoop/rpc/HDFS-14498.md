# HDFS-14498 — LeaseManager can loop forever on the file for which create has failed

## Commit

- **Hash**: `b6115597557`（trunk）；重复提交 `0bfd1b5a945`（branch-3.1 backport，同一 diff）
- **日期**: 2020-07-17 / 2020-07-13
- **涉及文件**: `hadoop-hdfs/.../namenode/FSNamesystem.java`（+11）；测试 `TestLeaseRecovery`

## Diff 机制分析

create 失败的文件可能在 namesystem 里留下半初始化状态（INode 存在但 lease/block 不完整）。LeaseManager.checkLeases 遍历到这种文件时，恢复路径无法推进又不将其从待处理集合移除，lease monitor 每轮都卡在同一文件——等价于无限循环（NN 锁内空转）。修复在 FSNamesystem 侧对 create 失败遗留的 UC 文件做兜底清理/跳过，保证 lease monitor 能推进。

## 影响评估

**中**。触发条件（create 中途失败）偶发，但一旦命中 lease monitor 持续空转将拖垮整个 NN 的响应（与 HDFS-15704 同族症状，修复点不同）。稳定性修复。
