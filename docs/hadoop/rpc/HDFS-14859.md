# HDFS-14859 — Avoid costly getNumLiveDataNodes when safemode min.datanodes is zero

## Commit

- **Hash**: `a3599c7e7055e3cf89c75e5c7453bb64f9e98589`
- **Date**: 2019-10-08
- **涉及文件**: `hadoop-hdfs/.../blockmanagement/BlockManagerSafeMode.java`（+测试）

## Diff 机制分析

`areThresholdsMet()` 每次 safemode 检查（每个 block report/心跳后都可能触发）
都调用 `getNumLiveDataNodes()`——该方法 O(N) 遍历全部 DN 描述符，即使
`dfs.namenode.safemode.min.datanodes=0`（默认，根本不需要这个数）。
修复：把 getNumLiveDataNodes 的求值推迟到 `blockSafe >= blockThreshold` 为真
且 datanodeThreshold>0 时才执行，短路掉大集群上高频的 O(N) 扫描。

## 影响评估

**低** — NN safemode 检查路径 CPU 优化：block report 密集期（NN 重启、
大量 DN 注册）可减少可观的重复 O(N) 计算；默认配置即可受益。

## apply 检查结果

**冲突**：`BlockManagerSafeMode.java`（areThresholdsMet 区与 3.1.1 上下文
不同，需手工合并）。
