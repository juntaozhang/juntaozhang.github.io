# HDFS-14720 — DataNode shouldn't report bad block when block length is Long.MAX_VALUE

## Commit

- **Hash**: `91790463684833742130d3085e265d9f6ec54393`
- **Date**: 2019-11-09
- **涉及文件**: `hadoop-hdfs/.../blockmanagement/ReplicationWork.java`

## Diff 机制分析

块删除但重建任务已在队列时，块 numBytes 被置为 `BlockCommand.NO_ACK`
（Long.MAX_VALUE）作哨兵。`ReplicationWork.chooseTargets()` 不判该哨兵，
拿着 Long.MAX_VALUE 的块大小去跑放置策略，按不可能满足的块大小选 DN，
选不出目标导致该重建工作反复失败，DN 侧还可能把源块上报为坏块。
修复：chooseTargets 前判断 `getBlock().getNumBytes() != BlockCommand.NO_ACK`，
哨兵块直接不设 targets，走正常的放弃/重排队路径。

## 影响评估

**低** — NN 重建调度与坏块上报的边界正确性：消除删除中块引发的无效调度
与误报坏块（误报会触发不必要的数据修复扫描）。

## apply 检查结果

**clean**。
