# HDFS-15036 — Active NameNode should not silently fail the image transfer

## Commit

- **Hash**: `ea0eeb8f1ab710cbe552c99afbbd41625656f8d0`
- **Date**: 2019-12-12
- **涉及文件**: `ImageServlet.java`、`StandbyCheckpointer.java`（+测试）

## Diff 机制分析

Standby 周期性把 fsimage 上传给 Active。Active 端 ImageServlet 的"最近已收过
checkpoint"限频检查原本不区分上传类型，把 rollback image、ckpt 文件的上传也
一并拒绝（403）；Standby 侧 StandbyCheckpointer 对非 SUCCESS 结果一律只置
isPrimary=false 静默吞掉。真实后果是 Active 在需要时拿不到 Standby 的 image，
HA 场景（尤其 rollback/滚动升级）checkpoint 链路悄悄失效。
修复：ImageServlet 限频检查仅限 `NameNodeFile.IMAGE`；StandbyCheckpointer 对
被拒绝的上传显式 `LOG.info` 说明原因。

## 影响评估

**中** — HA checkpoint 正确性/可观测性：静默失败改为显式拒绝+日志，避免
rollback/升级场景 checkpoint 链路静默断裂。
