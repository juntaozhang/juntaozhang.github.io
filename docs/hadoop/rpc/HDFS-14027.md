# HDFS-14027 — DFSStripedOutputStream 应实现两个 hsync 方法

## Commit

- **Hash**: `399645ebc16`（branch-3.1，2018-10-29，Xiao Chen）
- **涉及文件**（2 个，+35/-13）：`DFSStripedOutputStream.java`（hadoop-hdfs-client）、测试

## Diff 机制分析

EC（条带化）写流的 `hflush()`/`hsync()` 是 no-op（EC 尚不支持 hsync）。但 `DFSOutputStream` 新增的重载 `hsync(EnumSet<SyncFlag>)` 在 `DFSStripedOutputStream` 中**没有被 override**——走父类实现会真正执行 sync 语义，与 EC 流"不支持 sync"的约定冲突（hflush/hsync 直接返回不做事），调用方无法通过 `StreamCapabilities` 约定之外的路径被安全拒绝。

修复：override `hsync(EnumSet<SyncFlag>)` 为 no-op（与另外两个一致），并给三个方法加 debug 日志提示调用方应先检查 capability。

代码路径：应用对 EC 文件调用 hsync（如 HBase 在 EC 目录上的 WAL——非主流但存在）→ `DFSStripedOutputStream`。

## 影响评估

**评级：低**。仅 EC 写路径的方法签名补全；正常使用（检查 capability）无影响，修复语义不一致的边角。
