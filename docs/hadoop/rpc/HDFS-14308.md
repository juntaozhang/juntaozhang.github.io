# HDFS-14308 — DFSStripedInputStream curStripeBuf is not freed by unbuffer()

## Commit

- **Hash**: `44ca2fe4db37cfe2d7041278b7413a8f0f7b8c11`
- **Date**: 2019-10-26（GitHub PR #1667）
- **涉及文件**: `hadoop-hdfs-client/.../DFSStripedInputStream.java`（+测试）

## Diff 机制分析

`unbuffer()`（HBase/预读释放用）在 DFSStripedInputStream 未覆写，只释放父类的
block reader，子类持有的 `curStripeBuf`（一个 stripe 的 data buffer，MB 级 direct
内存）和 `parityBuf` 不还回 BUFFER_POOL，长期泄漏。修复：覆写 `unbuffer()`，
super.unbuffer() 后把两个 buffer put 回 pool 并置 null；顺手把 getParityBuffer()
加 synchronized 防并发分配。

## 影响评估

**中** — EC 读路径客户端内存泄漏：用 short-circuit/预读并依赖 unbuffer 的
长寿命进程（HBase RS 等）在 EC 文件上会持续吃 direct 内存。

## apply 检查结果

**clean**。
