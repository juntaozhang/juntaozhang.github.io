# HDFS-13840 — GS 更小的 RBW 块应加入 Corrupt 集合

## Diff 机制分析

DN 报告的块状态中 RBW/RWR（写进行中/恢复中）的处理：`checkReplicaCorrupt` 原来对"storedBlock 尚未 COMPLETE"的 RBW 报告一律 `return null`（不算损坏）。如果 DN 报告的 RBW 块 **generation stamp 比 BlockManager 里存的还小**（陈旧副本，如恢复后旧管道成员晚到上报），它不会被标记 corrupt，于是 `addStoredBlockUnderConstruction` 里"FINALIZED 且未在 replica 列表"的判断也因 `findStorageInfo` 已有记录而跳过 addStoredBlock——**陈旧 RBW 副本一直挂在块上，有效 FINALIZED 副本反而可能被当作多余副本删掉**，造成 missing。

修复：

1. RBW/RWR 分支：storedBlock 未 COMPLETE 且 `storedBlock.GS > reported.GS` 时，标记 `BlockToMarkCorrupt`（GENSTAMP_MISMATCH）；
2. `addStoredBlockUnderConstruction`：replica 此前是 corrupt 但现在恢复正常的，也要走 `addStoredBlock` 更新状态。

代码路径：DN blockReport / IBR → `BlockManager.processReport` → `checkReplicaCorrupt` / `addStoredBlockUnderConstruction`（NN 热路径）。

## 影响评估

**评级：中**。修复竞态下陈旧 RBW 副本干扰冗余管理的正确性问题，避免有效副本被误删导致的 missing；属于 NN 块状态机修复。
