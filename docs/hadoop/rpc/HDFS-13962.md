## Diff 机制分析

这是 **HDFS-13768 的 follow-up 修复**，无独立意义，必须与前述 commit 一起评估：

1. **避免无谓加锁**：`initializeAddReplicaPool` 是 synchronized 方法。HDFS-13768 让每个 BlockPoolSlice 构造都无条件调用它，而该方法本意只在静态池为 null 时初始化一次——每次构造都白白进入 synchronized。改为调用方先非同步判空，为 null 才进入同步初始化方法（经典 double-check 简化形态，虽非严格 DCL，但配合 synchronized 方法足够）。
2. **语义修正**：`ReplicaMap.addAndGet` 在锁内发现旧 replica 不存在时，`FoldedTreeSet.add()` 若遇到"等价但非同一对象"会拒绝插入并返回 false，导致 map 状态与返回值不一致；改为 `addOrReplace` 保证插入/替换语义正确（与 HDFS-13768 并行扫描下重复 block 裁决逻辑 `resolveDuplicateReplicas` 配合）。

代码路径：DataNode 启动 volume 扫描（同 HDFS-13768），无稳态路径。
