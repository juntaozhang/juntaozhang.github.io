# HDFS-15119 — Allow expiration of cached locations in DFSInputStream

## Commit

- **Hash**: `7dd43cec7f7f737e4998f5ca569eeac3f4919d9c`
- **Date**: 2020-01-24
- **涉及文件**: `DFSClient.java`、`DFSInputStream.java`、`HdfsClientConfigKeys.java`、`DfsClientConf.java`、`hdfs-default.xml`（+测试）

## Diff 机制分析

DFSInputStream 打开后 locatedBlocks 缓存终身不变：long-running reader
（如 Hive/Spark 大查询跑数小时）持有的 deadNodes 列表和块位置会全面过期——
DN 已扩容/退役、热点已迁移也无法感知，读一直打到老节点。新增客户端配置
`dfs.client.refresh.read-block-locations.ms`（默认 0 即关闭）：超时后在
`fetchBlockAt`/`blockSeekTo`/`readWithStrategy` 检查时间戳，过期则
`deadNodes.clear()` + `openInfo(true)` 重拉 locatedBlocks 并复位时间戳。

## 影响评估

**中** — 客户端读路径的可选性能特性：对长读场景显著改善 DN 负载分布与故障
恢复感知；默认关闭，行为不变，引入风险低。
