# HDFS-15199 — NPE in BlockSender

## Commit

- **Hash**: `64eb5b270941ce11ab9e3631d00ffaefe3335bca`
- **Date**: 2020-02-28
- **涉及文件**: `hadoop-hdfs/.../server/datanode/BlockSender.java`

## Diff 机制分析

`BlockSender.sendPacket()` 捕获 IOException 后对 `e.getMessage()` 直接
`startsWith(EIO_ERROR)`。当底层 NIO 异常 message 为 null（如某些 JVM/网络栈抛出
无 message 的 SocketException 包装）时抛 NPE，NPE 逃逸到 DataXceiver，
读请求以诡异方式失败且丢失原始错误信息。修复：外层加 `if (ioem != null)` 判空，
message 为 null 时跳过 EIO/断管判断，直接走原有 `ioeToSocketException(e)` 转换。

## 影响评估

**中** — DN 读路径（DataXceiver/BlockSender 是每次块读的必经热路径）。触发条件
窄（异常无 message），但一旦命中会把磁盘/网络错误变成 NPE，干扰上层重试与诊断。

## apply 检查结果

**冲突**：`BlockSender.java`（sendChunks 周边上下文与 3.1.1 有差异，需手工合并）。
