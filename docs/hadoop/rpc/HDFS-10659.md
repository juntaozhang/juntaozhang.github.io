# HDFS-10659 — JournalNode 重装后缺 paxos 目录导致 NameNode 崩溃

## Commit

- **Hash**: `dd795edcc74`（branch-3.1，2019-06-10，star / Hanisha Koneru）
- **涉及文件**（2 个，+18/-14）：`JNStorage.java`、`Journal.java`

## Diff 机制分析

QJM 的恢复协议（paxos-like recovery）需要读写 `$JN/current/paxos/<segmentTxId>` 文件。原实现 `getPaxosDir()` 只构造路径、不保证目录存在：paxos 目录只在 `format()` 时创建。如果 JN 的存储被重装/手工清理（`current` 目录重建但缺 paxos 子目录），后续 segment recovery 往 paxos 目录写文件直接抛 `FileNotFoundException`，进而导致 NN 崩溃或无法恢复日志段。

修复：`getPaxosDir()` 改为 `getOrCreatePaxosDir()`——不存在时 `mkdir()` 创建并记录日志；`getPaxosFile`、`purgeDataOlderThan`、`format`、`doUpgrade` 全部改走该入口，paxos 目录在任何路径下都保证存在。

代码路径：NN（active/standby）→ QJM `QuorumOutputStream`/recovery → JN RPC `prepareRecovery`/`acceptRecovery` → `Journal.getPaxosFile`；JN 侧 `purgeDataOlderThan` 后台清理。

## 影响评估

**评级：中**。HA 集群运维事故（JN 存储重建）后 NN 直接不可用的 hardening 修复，属于 QJM HA 写路径稳定性。
