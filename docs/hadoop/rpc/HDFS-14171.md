## Diff 机制分析

（backport 到 branch-3.1 时只带了 safemode 部分）`BlockManagerSafeMode.areThresholdsMet()` 每次检查都要调 `getDatanodeManager().getNumLiveDataNodes()`——全局锁下遍历全部 DN 的 O(N) 调用。

当 `dfs.namenode.safemode.min.datanodes`（datanodeThreshold）为 0（默认）时，这个数算出来根本不会被用到（`datanodeNum >= 0` 恒真）。

修复：`datanodeThreshold == 0` 时跳过 `getNumLiveDataNodes()` 调用。

代码路径：NN  safemode 检查（每次 blockReport/心跳后 `incrementBlockSafe` → `areThresholdsMet`）；NN 启动和 BR 风暴期间调用频率极高。

## 影响评估

**评级：低**。safemode 判定热路径省掉默认配置下的 O(N) 遍历；大集群 NN 启动/滚动重启期间可观测。
