# HDFS-14384 — DFSStripedInputStream lastLocatedBlock token 过期重取需 1~3s

## Commit

- **Hash**: `4690142e86bcf7b64804e27af0f4ff700988322a`
- **Date**: 2019-11-06
- **涉及文件**: `hadoop-hdfs-client/.../DFSInputStream.java`（+测试）

## Diff 机制分析

追加写文件的读，读到最后一个正在写的 block 时，由于块未 complete，重拉
locatedBlocks 走 `fetchBlockAt` 的 `insertRange` 分支——lastLocatedBlock 的
新 token 没有覆盖到（insertRange 只插中间段），拿着过期 token 打 DN 被拒
（InvalidToken），再走重试路径，每次 1~3s。
修复：fetchBlockAt 命中文件末尾块时整体替换 locatedBlocks 并更新
lastBlockBeingWrittenLength，使新 token 生效。

## 影响评估

**中** — 客户端读路径延迟：读写并发（如读正在写入的日志/ETL 管道文件）场景
反复吃 1~3s token 重试开销。
