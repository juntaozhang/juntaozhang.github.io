# HDFS-14492 — Snapshot memory leak

## Commit

- **Hash**: `a3493fe3288a3961cb85b8d50973d1563ffd3e35`
- **Date**: 2019-10-01（GitHub PR #1370）
- **涉及文件**: `INodeDirectory.java`、`INodeFile.java`、`snapshot/AbstractINodeDiffList.java`（+测试）

## Diff 机制分析

快照删除/清理后，INode 上的 DirectoryWithSnapshotFeature/FileWithSnapshotFeature
虽然 diff list 已空，feature 对象仍挂在 inode 的 feature 链表上不被移除——
每个残留 feature 带多个空 list 对象，快照 churn 大的 NN 堆上积累大量这种
空壳 feature。修复：`cleanSubtree` 清理后若 `sf.getDiffs().isEmpty()` 则
`removeFeature(sf)`（目录还要排除 DirectorySnapshottableFeature，该 feature
本身携带快照列表语义）。

## 影响评估

**中** — NN 元数据内存/GC：快照大量使用/删除场景可观测的堆增长，长期运行
的 NN 受益。

## apply 检查结果

**clean**。
