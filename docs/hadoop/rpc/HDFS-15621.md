# HDFS-15621 — Datanode DirectoryScanner uses excessive memory

## Commit

- **Hash**: `71a9885c978`
- **日期**: 2021-04-26
- **涉及文件**: `DirectoryScanner.java`、`FsVolumeSpi.java`（ScanInfo 重构）、`FsVolumeImpl.java`；测试 `TestDirectoryScanner`

## Diff 机制分析

`FsVolumeSpi.ScanInfo` 原来存的是 block/meta 文件的完整路径字符串（`blockSuffix`/`metaSuffix` 存相对或绝对路径，每个 block 两份字符串）。本 patch 重构为存三份更短的内容：`basePath`（所在目录完整路径）、`blockFile`（纯文件名）、`metaFile`（meta 文件名或后缀），需要完整路径时在 getter 里现拼。DirectoryScanner 每次全量扫描会为磁盘上每个 block 建一个 ScanInfo，大 DN（百万级 block）上这能把 scanner 的字符串内存占用降低一个量级，同时减少扫描期间的分配速率。

## 影响评估

**中**。DirectoryScanner 是 DN 常驻周期性任务，扫描期间内存尖峰曾导致大容量 DN OOM/频繁 Full GC；该重构直接缓解。对 GC 表现和 DN 稳定性是真实收益，不改变扫描语义。
