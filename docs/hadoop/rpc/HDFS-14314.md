## Diff 机制分析

DN 的 `BPServiceActor` 用 `fullBlockReportLeaseId` 走 BR lease 协议：heartbeat 时向 NN 申请 lease（返回 0 表示不批/无效），拿到正数 lease 后在随后的 `blockReport` RPC 里携带。

原实现 `fullBlockReportLeaseId` 是 `offerService()` 的**局部变量**——每次 `offerService` 重启（如 NN 重启后 DN 重新注册、`register()` 被调用）都从 0 重新初始化，看似没问题；但 lease 协议的真正 bug 是：`register()` 成功后没有重置 lease id，而 NN 侧（尤其 NN 重启后 BlockReportLeaseManager 状态变化）持有的 lease 状态已失效，DN 带着旧 lease/错误时序的 lease 上报，BR 被 NN 拒绝或延迟处理。

修复（backport 版本）：把 `fullBlockReportLeaseId` 提升为 `BPServiceActor` 实例字段，初始化为 0；`register()` 成功末尾显式重置为 0，下次 heartbeat 重新申请 lease。

代码路径：DN `BPServiceActor.offerService` 心跳循环 ↔ NN `blockReport` RPC（BR lease 协议双方）。

## 影响评估

**评级：中**。NN 重启/故障转移后 DN 的 full BR 时序正确性；lease 错乱会导致 BR 被拒、块汇报延迟一个周期。
