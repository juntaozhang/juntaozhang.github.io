# HDFS-15633 — Avoid redundant RPC calls for getDiskStatus

## Commit

- **Hash**: `8354ce680b8`
- **日期**: 2020-10-16
- **涉及文件**: `hadoop-hdfs-client/.../DFSClient.java`（+11/-2）

## Diff 机制分析

`DFSClient.getDiskStatus()`（`df` 命令 / `Filesystem.getStatus` 的底层）原来通过 `getStateByIndex(0/1/2)` 调三次 `namenode.getStats()` RPC，每次都走完整 NN RPC 往返。改为一次 `namenode.getStats()` 拿 `long[]`，本地按下标取值（并对数组长度做防御，不足返回 -1），RPC 次数 3→1。

## 影响评估

**低**。改动小、无风险；`getDiskStatus` 本身不是高频路径（监控/CLI 调用），但任何用到 `FileSystem.getStatus()` 的监控脚本、Spark/Hive 启动检查都会受益，且直接减少 NN 上无谓的 RPC 处理。

## apply 检查结果

**clean**。
