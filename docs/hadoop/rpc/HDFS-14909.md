# HDFS-14909 — chooseRandomWithStorageType should not decrease storage count for excluded node already in excluded scope

## Commit

- **Hash**: `14beaae65e68725635e428c237c79ba434b8b076`
- **Date**: 2019-10-17
- **涉及文件**: `hadoop-hdfs/.../net/DFSNetworkTopology.java`（+测试）

## Diff 机制分析

chooseRandomWithStorageType 遍历 excludedNodes 扣减 availableCount 时，
未跳过落在 excludedScope 子树内的节点——这些节点本就不在随机选择的候选集
（DFSNetworkTopology 按 scope 分层抽样），重复扣减使 availableCount 虚低，
可能误判无候选而放置失败。修复：扣减前判断 `excludedNode.getNetworkLocation()
.startsWith(excludedScope)` 则跳过。（注：此处的 startsWith 判断语义随后被
HDFS-14913 进一步用 isNodeInScope 修正，两个 patch 需一起考虑。）

## 影响评估

**低** — 块放置计数正确性：仅在使用 chooseRandomWithStorageType 的存储类型
感知放置路径、且有 scope 排除时触发。

## apply 检查结果

**clean**。
