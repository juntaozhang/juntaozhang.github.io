# HDFS-13730 — BlockReaderRemote.sendReadResult 抛 NPE

## Commit

- **Hash**: `fc8983a5b8c`（branch-3.1，2019-06-17，Yuanbo Liu）
- **涉及文件**（2 个，+6/-2）：`BasicInetPeer.java`、`NioInetPeer.java`（hadoop-hdfs-client）

## Diff 机制分析

远程读失败时，`BlockReaderRemote.sendReadResult(...)` 会记录诊断日志，日志参数里调用 `peer.getRemoteAddressString()`。`BasicInetPeer` / `NioInetPeer` 的实现是 `socket.getRemoteSocketAddress().toString()`——当 socket 已经关闭或未连接时，`getRemoteSocketAddress()` 返回 null → NPE。NPE 发生在错误处理路径里，会**掩盖原始 IOException**，让客户端拿到一个无意义的 NPE，读失败原因丢失、重试行为异常。

修复：两个 Peer 实现都改为先取 `SocketAddress`，为 null 则返回 null。

代码路径：DFSInputStream 读块 → `BlockReaderRemote.read` 失败 → `sendReadResult` 上报读结果（DataTransferProtocol 管道读，客户端读路径）。

## 影响评估

**评级：低-中**。改动极小；影响是错误路径的诊断信息质量——真实影响是 NPE 可能中断客户端正常的错误恢复/重试逻辑，属于客户端读路径稳定性修复。
