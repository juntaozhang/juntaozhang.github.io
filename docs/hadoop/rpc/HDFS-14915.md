# HDFS-14915 — Move Superuser Check Before Taking Lock For Encryption API

## Commit

- **Hash**: `4d4f5325bde5d789916bd481f2a7763e0f41fce7`
- **Date**: 2019-10-21
- **涉及文件**: `hadoop-hdfs/.../namenode/FSNamesystem.java`

## Diff 机制分析

`createEncryptionZone`/`listEncryptionZones`/`listReencryptionStatus` 等
把 `checkSuperuserPrivilege` 放在 namesystem 读/写锁内部——非超级用户的
常规请求也会先抢到锁再做权限检查，无意义地占用 NN 全局锁；reencrypt 路径
更是锁内检查失败才释放。修复：把超管检查挪到取锁之前（权限检查只需
FSPermissionChecker，无需锁）。

## 影响评估

**低** — NN 锁占用微优化：加密区管理 API 的权限失败请求不再占用全局锁；
对非加密区使用集群无影响。

## apply 检查结果

**冲突**：`FSNamesystem.java`（加密区方法区上下文与 3.1.1 有差异，需手工合并）。
