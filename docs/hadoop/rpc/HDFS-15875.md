# HDFS-15875 — Check whether file is being truncated before truncate

## Commit

- **Hash**: `7250f0e3273`
- **日期**: 2021-03-10
- **涉及文件**: `FSDirTruncateOp.java`、`FSNamesystem.java`、`BlockRecoveryWorker.java`、`DataNodeFaultInjector.java`；测试 `TestFileTruncate`

## Diff 机制分析

对处于 being-truncated 状态（已有 `truncateBlock` UC 状态、lease recovery 进行中）的文件再次发起 truncate 时，旧代码不检查该状态，可能与正在进行的 truncate/recovery 竞态，造成 block 状态错乱或恢复无法收敛。修复在 `FSDirTruncateOp.truncate` 的目标长度已达成分支前加入对 UC 状态 truncate 块的检查，抛 `AlreadyBeingCreatedException` 让客户端重试；BlockRecoveryWorker/DataNodeFaultInjector 一侧仅增加测试注入钩子。

## 影响评估

**中**。truncate + lease recovery 并发是低频但真实的竞态，触发后表现为 truncate 挂起/失败或 block 状态不一致；对 RPC 吞吐无影响，属稳定性正确性修复。
