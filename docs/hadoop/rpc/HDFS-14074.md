## Diff 机制分析

`ThrottledAsyncChecker.schedule()` 是 DN 磁盘健康异步检查（`VolumeCheck`、`DatasetVolumeCheck`）的入口。改动前代码：

```java
if (completedChecks.containsKey(target)) {
  final LastCheckResult<V> result = completedChecks.get(target);
  final long msSinceLastCheck = ... - result.completedAt;
```

`completedChecks` 是普通 `HashMap`（非并发），在 `containsKey` 与 `get` 之间另一线程（`removeAll()`，如磁盘被移除时）可删掉该 entry，`get` 返回 null → `result.completedAt` 抛 NPE → DN 注册流程失败（"DataNode failed to register to NameSpace"）。

修复：改为单次 `completedChecks.get(target)`，判 `result != null` 再使用，消除 TOCTOU 竞态窗口。

代码路径：DN 启动/运行期 `checkDiskError` → `FsDatasetImpl.checkAllVolumes` → `ThrottledAsyncChecker.schedule` → DataXceiver 收到写请求前的磁盘校验。

## 影响评估

**评级：中**。竞态窗口小但真实存在；一旦命中，DN 抛 NPE 并向 NN 注册失败，DN 无法加入集群，属于可用性/稳定性修复。
