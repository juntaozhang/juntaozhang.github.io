# HDFS-15421 — IBR leak causes standby NN to be stuck in safe mode

## Commit

- **Hash**: `d26dcf66869`
- **日期**: 2020-06-28
- **涉及文件**: `hadoop-hdfs/.../namenode/FSDirTruncateOp.java`、`FSEditLogLoader.java`；测试 `TestUpdateBlockTailing`（由 TestAddBlockTailing 改名）

## Diff 机制分析

Standby NN tail edit log 时，truncate 相关 op（updateBlock）应用后没有推进全局 generation stamp（`BlockIdManager.generationStamp`）。之后 Standby 自己处理 IBR（增量块报告）时，为块分配的新 GS 比全局 GS 小，IBR 被当作过期而丢弃/泄漏，块汇报对不上账——Standby 重启进入 safe mode 后永远达不到退出阈值。修复在 `FSDirTruncateOp.prepareFileForTruncate` 与 `FSEditLogLoader.updateBlocks` 两处应用 truncate op 时，用 `setGenerationStampIfGreater` 同步推进全局 GS。

## 影响评估

**高**。命中即 Standby 卡在 safe mode，HA 失去意义；truncate 属常规负载，EC/ truncate 使用多的集群风险高。正确性必修。

## apply 检查结果

**冲突**：测试文件 `TestAddBlockTailing.java` 在 3.1.1 中不存在（patch 中含重命名 hunk）；两个主代码文件 hunk 简单，可人工合入。
