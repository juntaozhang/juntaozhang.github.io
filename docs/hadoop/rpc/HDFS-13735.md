## Diff 机制分析

QJM 通过 HTTP 从 JN 下载 edit log 段（`URLImageViewer`/log segment fetch）。原实现 `URLConnectionFactory.newDefaultURLConnectionFactory(conf)` 使用 JVM 全局默认的 connect/read timeout（0 = 无限等待）。JN 网络分区/半死时，NN 下载线程**无限期阻塞**，拖住 tailing/checkpoint，严重时 SNN 长时间不更新、恢复时数据落后巨大；也无法按机房 RTT 调优。

修复：新增 `dfs.qjournal.http.open.timeout.ms` / `dfs.qjournal.http.read.timeout.ms`（默认 60000ms，即 `URLConnectionFactory.DEFAULT_SOCKET_TIMEOUT`），`QuorumJournalManager` 构造时用带超时参数的工厂。

代码路径：SNN/2NN `EditLogTailer` 下载 edits → `QuorumJournalManager` HTTP 拉取 JN 日志段。

## 影响评估

**评级：低**。HA 下 SNN tailing 路径的阻塞防护与超时调优；默认值行为与原先接近（原为无限等待，现在 60s），对分区场景是可用性改善。
