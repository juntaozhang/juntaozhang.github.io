# HDFS-15010 — BlockPoolSlice#addReplicaThreadPool should be initialized by static method

## Commit

- **Hash**: `5eb21b83dfd94cdd412e3b359a586d6441574f0a`
- **Date**: 2019-11-28
- **涉及文件**: `hadoop-hdfs/.../fsdataset/impl/BlockPoolSlice.java`（+测试）

## Diff 机制分析

`initializeAddReplicaPool` 是实例方法但初始化的是 static 的 addReplicaThreadPool，
依赖实例字段 `volume.getDataset()` 计算池大小。多 volume 并发构造时存在 TOCTOU：
两个实例都见 pool 为 null，池大小按其中一个的 volume 数计算；更隐蔽的是对
`volume` 字段的时序依赖（构造未完成即被使用）。修复：改为 static 方法，
FsDatasetImpl 显式传入，大小 = volumeCount * BPServiceCount 的口径统一；
并补测试用 reInitialize。

## 影响评估

**低** — DN 启动期静态线程池初始化竞态：主要影响是池大小可能按错误口径计算
（多 volume 下偏小），修复初始化一致性。
