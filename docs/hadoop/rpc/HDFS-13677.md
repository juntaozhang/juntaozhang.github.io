# HDFS-13677 — 动态刷新磁盘配置导致 VolumeMap 被覆盖

## Commit

- **Hash**: `7b51edbab9f`（branch-3.1，2019-04-29，xuzq）
- **涉及文件**（4 个，+105/-1）：`FsDatasetImpl.java`、`ReplicaMap.java` + 2 测试文件

## Diff 机制分析

DN 支持热插拔/动态增删数据盘（`reconfigure` 或 `dfs.datanode.failed.volumes.tolerated` 路径变化触发 volume 变更）。`FsDatasetImpl.activateVolume()` 把已有 volume 的 `ReplicaMap` 合并进全局 `volumeMap` 时，原实现用 `volumeMap.addAll(replicaMap)`，而 `ReplicaMap.addAll` 是 `map.putAll(other.map)`——**整体覆盖**该 block pool 下的嵌套 map，而不是逐条合并。动态刷新磁盘配置时这会**丢掉 volumeMap 里已有的其他盘上的 replica 记录**，DN 内存中大量 block "消失"，随后被 NN 判定 missing/触发重报，极端情况下造成数据不可用窗口。

修复：新增 `ReplicaMap.mergeAll()`——双层 map 逐条 `add(bp, replicaInfo)` 合并；`activateVolume` 改调 `mergeAll`。

代码路径：DN `DataNode.reconfigure`（动态磁盘配置）→ `FsDatasetImpl.addVolumes` → `activateVolume`。

## 影响评估

**评级：中-高**。运维动态调整磁盘配置（大集群常见操作）时直接破坏 DN 内存副本映射，导致假 missing 和 BR 风暴；属于 DN 数据面正确性修复。
