# HDFS-13941 — BlockPoolTokenSecretManager.checkAccess 的 storageId 改为可选

## Commit

- **Hash**: `8548864ccb5`（branch-3.1，2018-10-22，Ajay Kumar）
- **涉及文件**（3 个，+36/-2）：`BlockPoolTokenSecretManager.java`、`BlockTokenSecretManager.java`、测试

## Diff 机制分析

HDFS 分阶段升级/旧客户端场景：NN 颁发的 block token 里可能**不带 storageId**（旧版本 token 格式只含 storageTypes），而 DN 侧 `checkAccess` 走带 storageIds 的重载会严格比对 token 里的 storageIds 与请求中的 storageIds——格式不匹配直接抛 `InvalidToken`，**合法读/写请求被拒**。

修复：新增只按 `StorageType[]` 校验的 `checkAccess` 重载（先走基础校验，storageTypes 非空时才比对 storageTypes，不再强制 storageIds）；`BlockPoolTokenSecretManager` 暴露对应委托方法。RPC 层验证 token 密码后调用该重载，容忍无 storageId 的 token。

代码路径：DN `DataXceiver.checkAccess`（READ_BLOCK/WRITE_BLOCK 入口）→ `BlockPoolTokenSecretManager.checkAccess`。

## 影响评估

**评级：中**。影响滚动升级/混合版本集群的 block 访问授权成功率；属于 DN 数据面鉴权兼容性修复。
