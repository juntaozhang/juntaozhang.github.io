## Diff 机制分析

Router 向各 subcluster 并发发 RPC（`RouterRpcClient.invokeConcurrent` → `Call` 线程池，超时机制源自 HDFS-12273）。改动：

1. **RouterRpcClient.java（约 1007 行 `invokeConcurrent`）**：RPC 等待结果超时时，原来抛通用 `new IOException(msg)`，改为专用的 `new SubClusterTimeoutException(msg)`。异常本身不含新逻辑。
2. **新增 SubClusterTimeoutException**：`extends IOException` 的标记异常，用于区分"子集群超时"与"子集群返回 IO 错误"。
3. **NamenodeBeanMetrics.getNodesImpl()**：JMX `getLiveNodes`/`getDeadNodes` 聚合各 subcluster 的 datanode report 时，原来所有 IOException 走同一条 catch 并打全堆栈日志；现在单独 catch `SubClusterTimeoutException`，只打一行 "Cannot get {} nodes, subclusters timed out responding"，**不打堆栈**。
4. 测试新增 `testNamenodeMetricsSlow`：用 mock 让某个 NN 变慢，验证 live nodes 缓存（`NamenodeBeanMetrics` 有 DN report cache）超时后返回部分结果（2 个 DN → 0 个 DN），且不报错。

**机制本质**：这不是超时机制的算法改动，而是**超时错误的分类/可诊断性改进**——让 JMX 指标路径能优雅降级（部分 subcluster 超时时仍返回其余 subcluster 的数据），并避免监控抓取时刷错误堆栈日志。

## 对 RPC 性能的影响评估

**低**。

- 正常（无超时）路径行为完全不变：仅异常类型和日志路径不同。
- 收益场景是 subcluster 响应慢/挂掉时：监控 JMX 抓取不再被整体拖住或刷堆栈，但这属于可用性/可观测性，不改变 RPC 吞吐或延迟分布。仅 RBF Router 部署相关。
