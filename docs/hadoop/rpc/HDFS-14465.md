## Diff 机制分析

DN 进入 maintenance 前，NN 的 `DatanodeAdminManager` 要确认该 DN 上所有 block 都有足够剩余冗余（`isSufficient`）。原逻辑里 maintenance 与 decommission 共用一套充分性判断，只有 decommission 分支考虑"冗余度足以满足 decommission"的放宽条件；maintenance 场景缺少对应放宽：当 block 期望副本数（如 dfs.replication=5）大于集群 DN 总数时，`numLive >= expected` 永远不成立 → `isSufficient` 永远 false → DN 卡在 ENTERING_MAINTENANCE，永远退不出。

修复：`isSufficient` 增加 `isMaintenance` 参数；maintenance 场景下只要 live 副本数 ≥ `getMinReplicationToBeInMaintenance()`（默认 minReplication）即判定充分。

代码路径：NN 后台线程 `DatanodeAdminManager$Monitor` → `processBlocksInternal` → `isSufficient`（每次运行扫描 maintenance/decommission 队列中 DN 的全部块）。
