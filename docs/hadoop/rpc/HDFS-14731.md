# HDFS-14731 — [FGL] Remove redundant locking on NameNode

## Commit

- **Hash**: `4af188587fac752627ae25148f3608288146377b`
- **Date**: 2020-02-21
- **涉及文件**: `FSDirectory.java`、`FSNamesystem.java`、`BackupImage.java`、`EncryptionZoneManager.java`、`FSDirEncryptionZoneOp.java`、`ReencryptionHandler.java`（+测试）

## Diff 机制分析

FSDirectory 长期持有一把独立的公平 ReentrantReadWriteLock（dirLock），而所有调用点
都已先持有 FSNamesystem 的 fsLock——dirLock 是完全冗余的嵌套锁，每个目录操作多付出
一次 lock/unlock 及公平锁排队成本。本 patch 删除 dirLock 字段，
`FSDirectory.readLock/writeLock/hasReadLock/hasWriteLock` 退化为断言（断言调用者
已持有 namesystem 锁），`getInode()` 去掉多余的加锁包装；BackupImage/
EncryptionZone/ReencryptionHandler 中原来单独拿 dirLock 的几处改为直接拿
namesystem 锁。

## 影响评估

**低** — 纯锁开销精简：NN 每个元数据 RPC 少一层公平 RWLock 的获取/释放，微优化；
无行为变化，风险低。属于 FGL 系列的前置清理，不依赖 FGL 特性开关。
