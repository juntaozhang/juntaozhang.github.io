# HDFS-14366 — 提升 HDFS append 性能

- **Hash**: `80732146c6f`（branch-3.1，2019-03-15，Chao Sun）

## Diff 机制分析

HDFS append 需要 `BlockManager.isSufficientlyReplicated(lastBlock)` 判断最后一个块是否已有足够副本以支持 append。原实现：

```java
final int replication = Math.min(minReplication, getDatanodeManager().getNumLiveDataNodes());
return countNodes(b).liveReplicas() >= replication;
```

`getNumLiveDataNodes()` 每次都要在 `DatanodeManager` 全局锁下遍历全部 DN 统计 live 数——**大集群下是 O(N) 的昂贵调用**，而 append 是客户端同步 RPC 路径。绝大多数情况根本不需要这个数：副本数 ≥ minReplication（默认 1）就已足够判定。

修复：先比 `liveReplicas >= minReplication`（常量比较），不满足时才调用 `getNumLiveDataNodes()`。

代码路径：客户端 append RPC → `FSNamesystem.appendFile` → `BlockManager.isSufficientlyReplicated`（NN 热路径，尤其 HBase/Hive 大量 append 场景）。

## 影响评估

**评级：中**。把大集群 append 路径上每次一个 O(N) 降为常量比较；HBase 等 append 密集负载收益明显。
