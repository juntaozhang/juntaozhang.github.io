# HDFS-16040 — RpcQueueTime metric counts requeued calls as unique events

## Commit

- **Hash**: `a357d4ce607`
- **日期**: 2021-05-27
- **涉及文件**: `hadoop-common/.../ipc/Server.java`（+1）；`TestConsistentReadsObserver.java`（测试）

## Diff 机制分析

IPC Server 的 Handler 循环里，当 call 因一致性读取（observer/msync）原因被 `requeueCall(call)` 放回队列时，未将局部变量 `call` 置空，导致循环尾部对该 call 的 RpcQueueTime 计时/计数逻辑再次执行，一个 call 被统计成多次排队事件。修复是在 `requeueCall(call)` 之后加 `call = null;` 再 `continue`。纯指标正确性修复，不改变调度行为。

## 影响评估

**低**。只影响 RpcQueueTime 等 RPC 指标的准确性（使用 Observer/SBN 读场景下指标虚高），不影响真实 RPC 性能；但对基于该指标做容量判断的集群有意义。

## apply 检查结果

**冲突**：`Server.java` patch does not apply；测试文件 `TestConsistentReadsObserver.java` 在 3.1.1 中不存在。
