## Diff 机制分析

**根因**：对 EC（striped）块，`BlockManager` 在 `chooseSourceDatanodes` 和
`countReplicasForStripedBlock` 中用单个 BitSet 按 blockIndex 去重统计 live 副本
（同一 internal block index 只算一个 live，多出的算 REDUNDANT）。
但对 **DECOMMISSIONING** 副本完全没有做同样的按 index 去重，更没有考虑
"同一 index 既有 decommissioning 副本又有 live 副本"的覆盖关系：

- 某 internal block 在 dn0（decommissioning）和 dn4（live）各有一份，
  旧逻辑会把该 index 同时计入 live=1、decommissioning=1；
- `scheduleReconstruction` 依赖
  `additionalReplRequired = requiredRedundancy - live - decommissioning - ...`
  计算还需补几个 internal block，decommissioning 计数被 live 副本虚增后
  `additionalReplRequired` 被算成 0；
- 结果：该 striped block 既不调度重建、decommission 又等它"复制完成"——
  **decommission 流程永久挂起**（NN 内部监控线程空转，decommissioning 节点
  永远卡在 "Waiting for block replication"）。

JIRA 中的数值例子（RS-6-3-1024k）：dn0~dn3 在 decommission、dn4（持有 b4）宕机，
期望 decommissioning=3、additionalReplRequired=1；旧逻辑算出 decommissioning=4、
需求=0，重建永远不调度。

**修复方式**：

1. 新增 `countLiveAndDecommissioningReplicas(counters, state, liveBitSet,
   decommissioningBitSet, blockIndex)`，live / decommissioning 各用一个 BitSet
   按 blockIndex 去重，并建立覆盖语义：**同一 index 若已有 live 副本，
   后来的 decommissioning 副本不计数（减回 DECOMMISSIONING）**；
   live 副本重复则按原逻辑转 REDUNDANT。
2. `chooseSourceDatanodes` 和 `countReplicasForStripedBlock` 两处统一改调该方法。
3. `NumberReplicas.StoredReplicaState.DECOMMISSIONING` 注释明确：
   "for a striped block, this value excludes redundant and live replicas for the
   same internal block"。
4. `PendingReconstructionBlocks` 增加 `@VisibleForTesting getTimerThread()`，
   供新测试等待/驱动 pending reconstruction 监控线程。

## JIRA 页面信息

  10-31 解决）
- **触发场景**：EC 块组中一个或多个持有 internal block 的 DN 在 decommission
  期间恰好 out of service（宕机/维护），且同 index 存在 live 与 decommissioning
  副本重叠 → decommissioning 计数虚高 → 重建需求被低估为 0 → decommission 挂起。
  报告人原话："numReplicas.decommissioning() should be 3, it should exclude
  live replica."

## 影响评估

**中**。

- 影响 NN 内部 decommission 生命周期管理，不是 RPC 热点路径：
  挂起时 NN 自身读写 RPC 正常，但 decommission 中的 DN 无法完成退役，
  运维操作被无限期阻塞；若叠加 `dfs.namenode.decommission.max.concurrent.tracks`
  占满，还会阻塞后续所有退役操作。
- 仅限 EC 数据（striped block）+ DN 退役 + 节点宕机三者叠加场景；
  传统 3 副本复制不受影响。
- 对 NN RPC 客户端无直接感知，影响面小于 HDFS-13051/HADOOP-15684 类死锁。
