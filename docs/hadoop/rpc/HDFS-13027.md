# HDFS-13027 — 处理 deleted block 竞态引起的 NPE

## Commit

- **Hash**: `65977e5d812`（branch-3.1，2018-08-29，Vinayakumar B）
- **涉及文件**（4 个，+10/-3）：`BlockInfo.java`、`BlockManager.java`、`FSNamesystem.java`、`NamenodeFsck.java`

## Diff 机制分析

多个 NN 内部路径遍历块时，块可能已被并发删除（`BlockInfo.delete()` 把 `bcId` 置 0、解除与文件的关联），但遍历方拿到的 `BlockInfo` 引用仍在用：

1. `BlockManager.processExtraRedundancyBlocksOnInService` 迭代节点块列表时，`block.isDeleted()` 未检查 → 对孤儿块 `getExpectedRedundancyNum` 解引用已清空的 BlockCollection → NPE；
2. `FSNamesystem.clearCorruptLazyPersistFiles` 同样缺 `isDeleted()` 检查；
3. `NamenodeFsck.blockIdCK` 完全没有 namesystem 读锁保护，并发删除时拿到半删除状态的 BlockInfo → NPE/不一致输出；
4. `BlockInfo.bcId` 加 `volatile`（delete 与读取跨线程可见性）。

修复：补 `isDeleted()` 跳过/判空；fsck 补读锁。

代码路径：`refreshNodes`（decommission）、`clearCorruptLazyPersistFiles`（NN 后台）、`fsck blockId` 查询（NN 热路径管理操作）。

## 影响评估

**评级：中**。NN 写锁保护下的管理路径 NPE 会导致对应后台操作（decommission 处理、内存 LazyPersist 清理）中断；属于 NN 块管理竞态修复。
