# HDFS-15704 — Mitigate lease monitor's rapid infinite loop

## Commit

- **Hash**: `a23faaec184`
- **日期**: 2020-12-17
- **涉及文件**: `hadoop-hdfs/.../namenode/LeaseManager.java`（主代码）；`TestDeleteRace.java`（测试）

## Diff 机制分析

LeaseManager 原来维护 `leases`（TreeMap）+ `sortedLeases`（TreeSet，按 lastUpdate 排序）两份结构，每次 renew/add/remove 都要维护排序集合。问题场景：lease 的 lastUpdate 被 renew 到未来或系统时间回拨时，checkLeases 对 `sortedLeases.first()` 的检查出现恒真/恒假，触发 lease monitor 线程空转狂刷（rapid infinite loop），NN 锁被长期占用、RPC 大面积超时。修复直接删除 `sortedLeases` 结构，全部改用 `leases` HashMap + 遍历时比较，消除了排序结构带来的脆弱性，顺带减少每次 lease 操作的 TreeSet 维护开销。

## 影响评估

**高**。LeaseManager 在 NN 全局写锁下运行，其死循环会直接冻结整个 NN 的 RPC 服务；同时删 TreeSet 也略微降低 create/append/renew 的锁内开销。稳定性必修。

**冲突**：测试文件 `TestDeleteRace.java` patch does not apply；主文件 `LeaseManager.java` 的 hunk 基本可独立合入（需人工核对）。
