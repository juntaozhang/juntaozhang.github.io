# HDFS-12999 — 块组结束时无需两次 flushAllInternals

## Commit

- **Hash**: `354e63b366e22b04d8bfe72aa0eb2bb3e24f09b3`
- **Date**: 2019-12-25
- **涉及文件**: `hadoop-hdfs-client/.../DFSStripedOutputStream.java`

## Diff 机制分析

`DFSStripedOutputStream.writeChunk()` 在写完一个 stripe 时调用
`flushAllInternals()` 把全部 streamer 的包推给 DN；随后 `checkStreamerFailures()`
内部又无条件 `flushAllInternals()` 一次——同一个 flush 做了两遍，每个块组结尾
白白多一轮全 streamer 的同步等待。修复：给 `checkStreamerFailures` 加
`isNeedFlushAllPackets` 参数；块组结束路径（刚 flush 过）传 false，
stripe 中间路径（需要先把排队包推出去再判定失败）传 true，close 路径传 false。

## 影响评估

**低** — 纯 EC 写路径客户端优化：消除每块组一次冗余 flush，降低 EC 写的尾延迟
与网络往返；不影响正确性。
