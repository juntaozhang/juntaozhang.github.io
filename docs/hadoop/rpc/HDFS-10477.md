# HDFS-10477 — 停止整架 DN 的 decommission 导致 NameNode failover

## Commit

- **Hash**: `084fb9de22a`（branch-3.1，2019-04-03，yunjiong zhao / Wei-Chiu Chuang）
- **涉及文件**（1 个，+32/-12）：`BlockManager.java`

## Diff 机制分析

对一整架 DN 做 decommission 时，`DatanodeManager.refreshNodes` → `processExtraRedundancyBlocksOnInService` 需要在 NN **写锁**下遍历该节点所有 block 并逐个处理多余副本。原实现一个节点一个迭代器、**持锁一次跑完整个节点的全部块**——整架 DN 每节点数万到数十万块，写锁被长时间占用 → 心跳处理、其他 RPC 全部排队 → ZKFC 心跳超时 → active NN 被 fence，failover 到 standby。

修复：

1. 改为**按 storage 分批**遍历（`srcNode.getStorageInfos()` 外层循环），每批之间释放检查 storage 是否已移除；
2. 每处理完一个 storage 的块列表后，**释放写锁、sleep 1ms、重新加写锁**，让其他等待者（心跳/客户端 RPC）插队。

代码路径：`refreshNodes`（管理员执行 decommission）→ `BlockManager.processExtraRedundancyBlocksOnInService`（NN 写锁热路径）。

## 影响评估

**评级：高**。大规模 decommission 直接造成 NN 写锁饥饿并触发 HA 误切换；修复把长临界区切碎。属于 NN 锁公平性/可用性修复。
