# HDFS-15086 — Block scheduled counter never get decremented if block deleted before replication

## Commit

- **Hash**: `6a4297adc47befe87bef275e1f853df42fa70515`
- **Date**: 2020-02-13
- **涉及文件**: `BlockManager.java`、`DatanodeManager.java`、`PendingReconstructionBlocks.java`（+测试）

## Diff 机制分析

NN 调度重建时 `blocksScheduled` 计数（DN 维度的待复制上限，防热点）只在副本
上报（addBlock→decrement）时归还。若块在复制完成前被删除，或删除块被标记为
`NO_ACK(Long.MAX_VALUE)` 后仍随 DNA_TRANSFER 命令下发，`blocksScheduled` 永不
归还，该 DN 的调度额度被永久吃掉一块，长期累积后 DN 再也分不到复制任务。
修复贯穿三点：`PendingReconstructionBlocks` 的 target 类型由 DatanodeDescriptor
改为 DatanodeStorageInfo 以精确计数；`BlockManager.removeBlock` 删除 pending
项时归还其全部 targets 的 blocksScheduled；`DatanodeManager.handleHeartbeat`
下发复制命令时过滤 `NO_ACK` 删除块并归还计数。

## 影响评估

**中** — NN 冗余调度与 DN 负载均衡的正确性：写删 churn 大的集群会出现部分 DN
复制任务饿死，低冗余块重建变慢。
