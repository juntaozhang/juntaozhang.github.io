# HDFS-14497 — Write lock held by metaSave impacts following RPC processing

## Commit

- **Hash**: `d91c68729c18a2f853beb66b506ef9dff3526a38`（主修复，2019-05-30）
- **Hash**: `c61c114a3db021d1d86f290ce8fb6185582ed986`（Addendum，2019-08-27，`metaSaveLock` 改 final）
- **涉及文件**: `BlockManager.java`、`FSNamesystem.java`（+TestMetaSave）

## Diff 机制分析

`FSNamesystem.metaSave()` 原本持有 **写锁** 做全量元数据 dump（遍历所有
inode/block/DN），大集群上一次 metaSave 可耗时数秒到分钟，期间所有 NN RPC
全部阻塞。修复分两处：

1. `metaSave()` 改用**读锁**（dump 过程不修改状态），并用新增的
   `metaSaveLock` 对象做并发互斥（多个 metaSave 并发写同一文件的流交错问题）；
   `BlockManager.metaSave` 与 `FSNamesystem` 内部 metaSave(PrintWriter) 的
   锁断言相应从 hasWriteLock 放宽为 hasReadLock。
2. Addendum 把 metaSaveLock 声明为 final（代码规范/防意外重赋值）。

## 影响评估

**中** — NN 可用性：运维在大集群执行 `dfsadmin -metaSave` 不再全局阻塞
RPC；读锁下 dump 与并发写仍受 fsLock 读-写互斥保护，dump 内容一致性可接受。
