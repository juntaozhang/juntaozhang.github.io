# HDFS-14553 — BlockReportProcessingThread 队列大小可配置

## Commit

- **Hash**: `03ec4c4c7c1`（branch-3.1，2019-06-10，He Xiaoqiao）
- **涉及文件**（3 个，+21/-5）：`DFSConfigKeys.java`、`BlockManager.java`、`hdfs-default.xml`

## Diff 机制分析

NN 的异步块报告处理线程 `BlockReportProcessingThread`（`BlockManager` 内部类）使用固定 1024 容量的 `ArrayBlockingQueue<Runnable>` 存放待处理 block report。大集群全量 BR 风暴期间（大量 DN 同时上报），1024 的容量可能被打满，`offer` 失败导致 report 被丢弃/延迟。

修复：队列容量改为由新配置 `dfs.namenode.blockreport.queue.size`（默认 1024，行为不变）注入；`BlockReportProcessingThread` 构造函数接收 size。

代码路径：DN `blockReport` RPC → `BlockManager.queueBlockReport` → 队列；消费侧线程批量取出后在有限持锁窗口内处理。

## 影响评估

**评级：低**。纯可配置化，默认值不变；对大集群 BR 尖峰有调优价值，避免队列打满造成的 BR 丢失重试。
