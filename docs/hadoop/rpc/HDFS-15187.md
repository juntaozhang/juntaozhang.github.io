## Diff 机制分析

Standby NN 在 failover 前以延迟队列处理 corrupt 上报，切换 Active 时队列中的块若与实际副本状态不符，会在新 Active 上被错误标记为 CORRUPT 而 ANN 不会，造成两个 NN 的副本状态分歧（客户端读到不一致）。修复收紧 `processAndHandleReportedBlock`/corrupt 处理路径，对已排队但状态已变化的块重新核对 generation stamp 与副本存在性，避免 stale corrupt 判定跨 failover 生效。

## 影响评估

**中**。影响 HA failover 场景下块元数据的一致性，可引发误报的 missing/corrupt block 告警与不必要的复制调度；非常驻热路径但属正确性修复。
