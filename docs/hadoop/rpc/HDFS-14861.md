## Diff 机制分析

`LowRedundancyBlocks.chooseLowRedundancyBlocks()` 用 bookmark 在优先级队列上
断点续扫，只有扫到队列末尾才重置 bookmark。若低冗余队列持续增长（大量块报告、
decommission、坏盘），bookmark 永远到不了队尾，排在 bookmark 之前的块长期
得不到调度重建——低冗余块可能挂数小时。修复：新增
`dfs.namenode.redundancy.queue.restart.iterations`（默认 2400，约 2 小时），
`computeBlockReconstructionWork` 每调用 N 次强制重置一次各队列 bookmark。

## 影响评估

**中** — NN 冗余调度正确性/时效性：大集群或持续有大量低冗余块时，缺此修复部分
块重建会被无限期推迟，直接影响数据可靠性 SLA。
