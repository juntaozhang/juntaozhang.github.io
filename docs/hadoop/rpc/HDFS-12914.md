## Diff 机制分析

Block report lease（BR lease）机制：DN 申请 full block report lease 后，NN 在 `processReport` 内逐个 storage 校验 lease，lease 过期或不匹配则**静默丢弃该 report**（返回 false）。

改动前 lease 校验放在 `BlockManager.processReport` 内部、**按 storage 逐个进行**——DN 一个 RPC 携带多个 storage 的 report，只有第一个 storage 的 report 有 lease 上下文，后续 storage 的 report 进入 `processReport` 时 lease 已被 `removeLease` 移除，导致**同一次 RPC 里后面的 storage 报告被丢弃**，这些块在下一次 block report 之前一直显示 missing。

改动内容：

1. `BlockManager` 新增 `checkBlockReportLease(context, nodeID)`：在进入逐 storage 循环**之前**统一校验一次 lease（context 为 null 直接放行）。
2. `NameNodeRpcServer.blockReport`：把 lease 检查从 `processReport` 循环内上移到循环外，一次检查、全部处理；捕获 `UnregisteredNodeException` 时向 DN 返回 `RegisterCommand.REGISTER` 而不是让 RPC 抛异常。

代码路径：DN → `blockReport` RPC → `NameNodeRpcServer.blockReport` → `BlockManager.processReport`（NN 热路径，全量 BR 期间每次心跳批量到达）。

## 影响评估

**评级：高**。直接导致块被误判 missing（监控告警、可能触发不必要补副本），且在 BR 间隔（默认 6 小时）内持续存在；对多 storage（多磁盘）DN 几乎必现。属于 NN block report 热路径的正确性修复。
