# HDFS-15012 — NN fails to parse Edit logs after applying HDFS-13101

## Commit

- **Hash**: `280cd6dd1ee945342d63333269842280f7ea59ed`
- **Date**: 2019-12-18
- **涉及文件**: `hadoop-hdfs/.../namenode/snapshot/DirectoryWithSnapshotFeature.java`（+测试）

## Diff 机制分析

HDFS-13101 改动后，快照目录清理（cleanDirectory）在销毁 createdList 前只看
`currentINode.isLastReference()`。当目录被多次快照引用、且当前处理的 prior diff
并非最后一个快照 diff 时（`getLastSnapshotId() != prior`），销毁 createdList 会
把后续快照仍需引用的 created 项删掉，之后 NN 重放含这些快照的 editlog 或加载
fsimage 时元数据不一致，报 edit log 解析失败。
修复：销毁条件追加 `getDiffs().getLastSnapshotId() == prior`，只在真正最后的
快照 diff 上销毁。

## 影响评估

**高** — 快照+重命名 churn 场景可造成元数据损坏，导致 NN 重启时 edit log
解析失败无法启动，属数据可靠性/可用性级缺陷（HDFS-13101 已在 3.1.1 中，此为其回归修复）。
