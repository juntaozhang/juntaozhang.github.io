# HDFS-15703 — Don't generate edits for set operations that are no-op

## Commit

- **Hash**: `521d5b381a9`
- **日期**: 2020-12-02
- **涉及文件**: `hadoop-hdfs/.../namenode/FSDirAttrOp.java`；测试 `TestFSDirAttrOp`

## Diff 机制分析

`setPermission`/`setOwner` 即使权限/属主未发生变化（no-op）也照常写一条 edit log 记录，制造无意义的事务和 fsimage 差异。修复让 `unprotectedSetPermission`/`unprotectedSetOwner` 返回 boolean（新旧 permission long 比较），`changed == false` 时跳过 `logSetPermissions`/`logSetOwner`。批量 chmod/chown 作业（hive/spark 输出目录）由此大量减少 edit log 体积与 JournalNode 同步流量。

## 影响评估

**中**。直接降低 edit log 写放大与 SBN/JN 的 tail 压力，对 edit 密集负载的 HA 集群有可见收益；同时不改变任何语义（no-op 不写日志本就符合预期）。

**clean**。
