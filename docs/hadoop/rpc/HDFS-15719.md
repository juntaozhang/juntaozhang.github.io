# HDFS-15719 — Both NameNodes can crash simultaneously due to the short JN socket timeout

## Commit

- **Hash**: `13768fe6f0c`
- **日期**: 2021-01-04
- **涉及文件**: `CommonConfigurationKeysPublic.java`、`HttpServer2.java`、`core-default.xml`、`kms-default.xml`、`httpfs-default.xml`

## Diff 机制分析

把 `hadoop.http.idle_timeout.ms` 的默认值从 1000ms（HttpServer2 内代码默认 10s 也一并统一到 60s）提高到 60000ms。JN 间 edit log 传输、NN checkpoint 的 ImageServlet 传输、KMS/HttpFS 会话都跑在 Jetty HTTP 通道上；1s 空闲超时在 GC 停顿、网络抖动或大 fsimage 慢传输时会话被掐断，QJM 写 edit 失败可同时击倒两个 NN（双 NN 崩溃 = 全集群不可用）。

## 影响评估

**高**。纯配置默认值变更，风险极低，直接消除一类导致 HA 双机同崩的定时炸弹。虽属 HTTP 层，但承载的是 QJM/checkpoint 等核心 HA 数据通道，应合入。

## apply 检查结果

**冲突**：`CommonConfigurationKeysPublic.java`、`HttpServer2.java` patch does not apply（默认值上下文与 3.1.1 不一致）；改动本身只是数值，人工改两处常量即可。
