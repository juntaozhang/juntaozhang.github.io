# HDFS-15641 — DataNode could meet deadlock if invoke refreshNameNode

## Commit

- **Hash**: `eb909fd726a`
- **日期**: 2020-10-26
- **涉及文件**: `hadoop-hdfs/.../datanode/BPOfferService.java`、`BPServiceActor.java`；测试 `TestRefreshNamenodes`

## Diff 机制分析`

`refreshNameNode`（动态增删 NN 地址，例如 observer 上线）与 BPServiceActor 线程的启动/停止并发时存在锁序不一致：BPOfferService 持锁期间启动 actor 线程，actor 启动后又回头取 BPOfferService 的锁，构成持锁-等锁环。修复调整 `BPServiceActor.start()` 的调用位置（移出持锁区），使线程启动不发生在 BPOfferService 锁保护区内。

## 影响评估

**高**。死锁一旦发生，DN 的该 blockpool 心跳/IBR 全部停摆（表现为 DN 僵死、NN 标记 lost）；运维执行 refreshNameNode 即触发。改动小，稳定性必修。

## apply 检查结果

**clean**。
