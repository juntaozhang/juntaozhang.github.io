# Multimodal RAG System

---

## 一、基础概念

| 缩写      | 全称                          | 说明                              | 典型工具/模型            |
|-----------|-------------------------------|-----------------------------------|--------------------------|
| **ASR**   | Automatic Speech Recognition  | 语音识别，将音频转为文字          | Whisper                  |
| **OCR**   | Optical Character Recognition | 光学字符识别，提取图片中的文字    | EasyOCR                  |
| **VLM**   | Vision-Language Model         | 视觉语言大模型，具备图像理解能力  | GPT-4V, Qwen-VL, LLaVA   |

> **关键区别**：ASR 和 OCR 只能提取文字，不具备图像理解能力；VLM 能理解画面内容，弥补纯 OCR 的缺陷。

## 二、多模态 RAG 系统搭建流程

### 2.1 整体架构

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│   音频数据   │   │   图片数据   │   │   视频数据   │
└──────┬──────┘   └──────┬──────┘   └──────┬──────┘
       │                 │                 │
       ▼                 ▼                 ▼
┌─────────────┐   ┌─────────────┐   ┌──────────────────┐
│  ASR 转录   │   │ OCR + VLM   │   │ 关键帧采样 + VLM  │
│ 带时间戳文稿 │   │ 文字 + 描述  │   │ 画面描述 + ASR   │
└──────┬──────┘   └──────┬──────┘   └────────┬─────────┘
       │                 │                   │
       └─────────────────┴───────────────────┘
                         │
                         ▼
              ┌──────────────────┐
              │  数据归一化       │
              │ 统一转为结构化文本 │
              │ (来源/时间戳/类型) │
              └────────┬─────────┘
                       │
                       ▼
              ┌──────────────────┐
              │  向量嵌入 + 向量库  │
              │ 存入同一向量空间   │
              └────────┬─────────┘
                       │
                       ▼
              ┌──────────────────┐
              │  多模态 RAG 应用  │
              │ 可溯源问答        │
              └──────────────────┘
```

### 2.2 各模态处理细节

| 模态       | 处理方式                                     | 输出               | 关键要点                           |
|------------|----------------------------------------------|--------------------|------------------------------------|
| **音频**   | ASR 模型转录                                 | 带时间戳文字文稿   | 解决语音数据检索问题，保留时间信息 |
| **图片**   | OCR 提取文字 + VLM 生成场景描述              | 结构化文本片段     | 弥补纯 OCR 无法理解画面内容的缺陷  |
| **视频**   | 定时采样关键帧 → VLM 生成画面描述 + 音频转录 | 带时间戳的时序描述 | 捕捉随时间变化的事件信息           |

### 2.3 数据归一化标准

所有模态信息统一标准化为**带元数据的文本片段**：
- `source`：数据来源（文件名/URL）
- `timestamp`：时间戳（音频/视频）
- `type`：模态类型（audio/image/video）
- `content`：文本内容（ASR 转录 / OCR 结果 / VLM 描述）

## 三、数据增强

### 3.1 三类增强方式

| 类型             | 说明                             | 适用场景                 |
|------------------|----------------------------------|--------------------------|
| **离线增强**     | 预先对数据集做变换后持久化存储   | 数据量较小，计算资源充足 |
| **在线增强**     | 训练时实时做变换，不修改原始数据 | 数据量大，需要多样性     |
| **仿真合成增强** | 仿真引擎从零生成完整场景时序     | 现实难以采集的极端场景   |

### 3.2 自动驾驶场景增强示例

- 天气变换：雨天、雪天、雾天、强光
- 物理干扰：遮挡、模糊、运动模糊
- 传感器异常：视觉失灵、感知矛盾、极端 case
- 仿真生成：突发横穿马路、逆行、施工区域等

### 3.3 时序数据增强约束

> ⚠️ **时序数据不能随便打乱顺序！**

允许的增强操作：
- 噪声叠加
- 时间拉伸 / 压缩
- 局部掩码
- 通道扰动
- 采样频率调整
- 缺失值模拟

**校验标准**：增强后训练集 / 验证集分布不能发生漂移，需做输出分布校验。

## 四、多层标签体系（以自动驾驶数据集为例）

### 4.1 三层标签结构

```
┌─────────────────────────────────────────────────────┐
│  L1: 基础真值标签 (Ground Truth)                     │
│  ├── 2D 边界框                                       │
│  ├── 3D 边界框                                       │
│  └── 车道线                                          │
├─────────────────────────────────────────────────────┤
│  L2: 场景属性标签 (Scene Attributes)                 │
│  ├── 光照: 白天 / 夜间 / 黄昏                        │
│  ├── 天气: 晴天 / 雨天 / 雪天 / 雾天                 │
│  ├── 道路: 高速 / 城区 / 园区 / 乡村                 │
│  └── 交通: 拥堵 / 空旷 / 缓行                        │
├─────────────────────────────────────────────────────┤
│  L3: 工况标签 (Operational Conditions)               │
│  ├── 车辆行为: 直行 / 转弯 / 变道 / 掉头             │
│  ├── 行人行为: 横穿 / 路边停留 / 逆行                │
│  └── 障碍物状态: 静止 / 运动 / 突然闯入              │
└─────────────────────────────────────────────────────┘
```

### 4.2 多层标签的作用

不只是输出一个总体 mAP，可以**拆分维度**看模型表现：
- 雨天场景下的行人检测精度
- 夜间场景下的车道线识别召回率
- 行人横穿工况下的响应延迟

→ **定位短板，精准优化**

## 五、数据集划分策略

### 5.1 拆分原则

| 集合         | 用途               | 要求               |
|--------------|--------------------|--------------------|
| **训练集**   | 模型训练           | 覆盖所有场景类型   |
| **验证集**   | 超参调优、早停     | 与训练集分布一致   |
| **测试集**   | 最终评估、横向对比 | 严格隔离，不可泄露 |

### 5.2 自动化校验

1. **样本互斥校验**：确保同一样本不会同时出现在多个集合中
2. **分布校验**：训练 / 验证 / 测试集的场景分布、特征分布不能出现明显偏移
3. **防止数据偏移（Data Shift）**

### 5.3 版本管理

- 每次新增数据、重新划分后生成新版本 **Snapshot**
- 支持**回滚**到历史版本
- 支持**对比**两个版本划分差异

### 5.4 冷热分层存储

| 层级         | 存储介质            | 数据类型         | 目的               |
|--------------|---------------------|------------------|--------------------|
| **热数据**   | SSD                 | 高频训练数据集   | 快速读取，加速训练 |
| **冷数据**   | 对象存储 / 归档存储 | 历史旧训练数据集 | 控成本，长期保留   |

### 5.5 增量迭代训练的数据集管理

**❌ 错误做法**：简单把新样本合并旧数据集，每次重新随机划分
- 问题：测试集不断变化，模型精度 92 → 90，分不清是数据问题还是模型退化

**✅ 正确做法**：

| 模式                   | 策略                               | 适用场景                    |
|------------------------|------------------------------------|-----------------------------|
| **增量持续训练模式**   | 固定基准测试集，增量只追加进训练集 | 快速迭代，频繁发版          |
| **周期性重训模式**     | 定期全量合并，整体重新划分         | 大版本升级，季度/年度重训   |

> 固定测试集的作用：所有模型版本跑同一套测试集，横向公平对比指标，做回归测试。

## 六、离线批量预测（难例挖掘 & 自动评测）

### 6.1 流程

```
┌─────────────────┐
│ 准备预测输入数据集 │
│ 统一格式批量喂入  │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   模型批量推理   │
└────────┬────────┘
         │
         ▼
┌──────────────────────────┐
│ 预测结果与原始样本 Join   │
│ （核心步骤！确保可溯源）   │
└────────┬─────────────────┘
         │
         ▼
┌──────────────────────────┐
│ 筛选 Bad Case            │
│ 预测与真值偏差大的样本    │
│ 自动入库 → Case 库        │
└────────┬─────────────────┘
         │
         ▼
┌──────────────────────────┐
│ 流入数据闭环              │
│ 补充标注 → 重新训练       │
└──────────────────────────┘
```

### 6.2 核心要点

- **Join 是关键**：预测结果必须和原始样本关联，否则无法定位问题
- 这是自动驾驶数据闭环的关键一环：**批量推理 → 挖掘坏例 → 补充数据 → 模型迭代**

## 七、线上实车推理（无人车运行时）

数据工程师的核心职责：**回流管道建设**

### 7.1 数据回流链路

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   无人车端    │ ──▶ │   云端回流    │ ──▶ │  难例候选池   │
│ 异常场景触发  │     │ 管道处理     │     │  等待挖掘标注  │
└──────────────┘     └──────────────┘     └──────────────┘
```

### 7.2 具体步骤

1. **异常样本回传链路**
   - 车端识别到高不确定度、异常场景
   - 将传感器数据（摄像头、激光雷达、毫米波雷达）上传云端

2. **回流数据标准化**
   - 数据清洗
   - 元信息补齐：车辆 ID、时间、地理位置、工况标签

3. **实时 / 准实时入库**
   - 使用 Flink 等流处理框架
   - 纳入候选难例池
   - 等待后续挖掘、标注、回流训练

## 八、补充：时间序列数据交叉增强

> 原文提到"时间序列对不同的数据集的数据交叉"，补充说明：

在多模态 RAG 场景中，时间序列交叉指的是：
- **音频时间戳** 与 **视频关键帧时间戳** 对齐
- 同一时间段内的多模态信息（语音 + 画面 + OCR 文字）做交叉验证
- 提升检索精度和回答可信度
